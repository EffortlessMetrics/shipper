# Scheduler conformance ledger for 0.5.0

Status: In progress
Owner: Shipper swarm maintainers
Milestone: 0.5.0 release blockers
Linked issue: [#153](https://github.com/EffortlessMetrics/shipper-swarm/issues/153)
Source seam: `crates/shipper-core/src/engine/parallel/tests.rs`

This ledger is the acceptance map for the final #153 conformance closeout. It
records current evidence on `origin/main` and separates existing focused proof
from the cross-scheduler comparisons still required. Timestamps, temporary
paths, and other genuinely nondeterministic values may be normalized; semantic
state, events, receipts, invocation counts, and diagnostics may not.

## Contract

For each scenario that has a sequential analogue, run the same fixture through
the sequential and parallel schedulers and compare. Event comparison is a
partial-order check: preserve lifecycle order within each package, enforce
dependency and scheduler-level ordering, and treat events from independent
packages as interchangeable when their interleavings differ validly.

| Evidence | Required comparison |
| --- | --- |
| Package result | status, success/failure, and error class |
| State | terminal state, attempts, and prior progress |
| Events | semantic event partial order, including per-package lifecycle and dependency/level ordering |
| Rebuild | event-to-state projection for every claimed reconstructible field |
| Receipt | status, reason, execution result, and evidence |
| Cargo | invocation count and no duplicate upload |
| Webhooks | run/package event counts and failure contract |
| Reporting | buffered messages reach the caller |

Worker panic/join failure has no sequential analogue. It is therefore a
parallel-only contract: the caller receives a run-level error, synchronized
state is durable, and buffered reporter output is replayed before return.

## Closeout requirements

The implementation PR may close #153 only when:

1. Every row above is linked to an exact test or explicitly marked as the
   parallel-only worker failure contract.
2. The shared executor remains the only package-execution authority.
3. The shared corpus compares semantic events, rebuilt state, receipts, Cargo
   calls, webhooks, and reporter output where the scenario applies.
4. The issue body is updated to remove obsolete duplicate-authority paths and
   links this ledger plus the exact-head test evidence.
5. The complete routed Rust gate and the focused conformance command pass on
   the final PR head.

## Proof commands

```text
cargo fmt --all -- --check
cargo nextest run -p shipper-core --lib --locked --profile ci
cargo nextest run -p shipper-cli --test bdd_parallel --locked --profile ci
cargo nextest run -p shipper-cli --test e2e_rehearse --locked --profile ci
cargo xtask policy-report
git diff --check
```

The ignored live interruption rehearsal is a separate release-evidence gate;
local execution does not replace its hosted self-hosted-runner check.

## Non-goals

- No new public crate or public executor type.
- No broad module-topology cleanup.
- No release publication, tag, credential, or release-authority mutation.
- No normalization that hides a semantic sequential/parallel disagreement.

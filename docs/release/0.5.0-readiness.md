# 0.5.0 Release-Candidate Readiness

Status: candidate preparation in `shipper-swarm`; not published

The swarm repository is the development and proof surface. The separate
`EffortlessMetrics/shipper` repository remains the release authority for the
0.5.0 tag, crates.io publication, GitHub Release, signing, and release
credentials. This document records claims to carry into that authority; it is
not publication authorization.

## Stabilized implementation

- Sequential and parallel schedulers delegate package behavior to one internal
  execution authority.
- Durable transitions are event-first: `events.jsonl` is truth, `state.json` is
  a projection, and `receipt.json` is a derived summary.
- Readiness polling has one shared kernel with attempt, backoff, actual-sleep,
  timeout, cancellation, and visibility evidence.
- Resume skips, run-start notifications, ambiguous outcomes, and worker/join
  failures have explicit evidence contracts.
- Registry destinations, redirects, private-network opt-in, and credential
  authority are validated at the network boundary.
- Authorization redaction is context-aware; webhook secrets are excluded from
  execution evidence and diagnostic surfaces.
- New encryption writes use KDF v2 / 600,000 PBKDF2-HMAC-SHA256 iterations;
  unversioned KDF v1 artifacts remain decryptable at 100,000 iterations.
- Blank or whitespace-only OIDC request variables are unavailable and are
  diagnosed without exposing values.

### Webhook-secret data-flow audit

`WebhookConfig` remains serializable because the configuration crate uses
serde/TOML round-tripping for user configuration. That serialization boundary
is not used to create `events.jsonl`, `state.json`, `receipt.json`, structured
command output, or diagnostic messages: those surfaces serialize their own
event, state, receipt, report, and finding types and do not contain
`WebhookConfig` or `RuntimeOptions`.

The runtime configuration type has a manual `Debug` implementation that
redacts both the webhook URL and signing secret. The webhook crate's secret-
bearing snapshot now exercises that redacted diagnostic path, and its fixture
value is assembled at runtime rather than stored as a credential-like literal.
Configuration serialization remains covered by the explicit configuration
round-trip tests; diagnostic snapshots do not serialize the live secret.

## Compatibility guarantees

0.5 artifacts are rebuildable for every field claimed by the event vocabulary.
0.4 events, state, and receipts remain readable and safely resumable; fields
unknown to the 0.4 vocabulary remain unknown rather than fabricated.

## Required exact-SHA evidence

The final candidate bundle must be tied to one immutable swarm SHA and include:

- routed Rust formatting, Clippy, nextest, docs, policy, and package-surface
  proof;
- `shipper-core` conformance plus CLI parallel and interruption/resume tests;
- 0.4 fixture load/resume and KDF v1/v2 compatibility;
- webhook and authorization non-disclosure matrix;
- registry destination, resolved-address, redirect, and credential-authority
  matrix;
- topological package dry-run, facade install smoke, version/help smoke, and
  semver reports against 0.4.0;
- release-workflow target-platform, publication-order, and interrupted-train
  resume evidence.
